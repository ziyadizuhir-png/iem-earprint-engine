# General Prompt EarPrint 8 — MATH LOCKED
# Boundary / Adaptive Handoff Addendum
# Version: 1.0

============================================================
1. PURPOSE
============================================================

This addendum defines the boundary behavior for the target-specific
Robust Target when the nominal 1 kHz splice is not locally compatible
with the target's natural shape.

The nominal 1 kHz anchor remains the declared personal-domain boundary.
It is NOT an unconditional splice point.

The objective is to preserve the selected target naturally below the
personal domain while introducing the target-specific masked EarPrint
without creating an artificial kink, dip, hump, overshoot, undershoot,
local extremum, oscillation, or unintended slope reversal.

============================================================
2. LOCKED LOWER-BOUNDARY RULE
============================================================

For every target:

    BaseTarget(f) is preserved exactly for f <= 1000 Hz.

The engine must never alter the target below or at the nominal 1 kHz
anchor as a consequence of the adaptive handoff.

The 1 kHz anchor is therefore a reference boundary, not necessarily the
actual transition frequency.

============================================================
3. NOMINAL 1 kHz COMPATIBILITY TEST
============================================================

Before searching for a later handoff, evaluate whether the nominal
1 kHz boundary is locally compatible.

The compatibility test must consider:

- local target slope direction;
- local masked-EarPrint slope direction;
- local shape stability;
- absence of an unintended local extremum or slope reversal.

If the nominal boundary is compatible, retain the existing masked
curve without introducing an adaptive bridge.

If it is incompatible, do not force the splice at 1 kHz.

============================================================
4. ADAPTIVE HANDOFF SEARCH
============================================================

When the nominal 1 kHz boundary is incompatible:

1. Preserve BaseTarget exactly through 1 kHz.
2. Search upward in frequency for the earliest stable compatible
   handoff H.
3. Determine an endpoint E within the configured personal domain.
4. Require the transition H -> E to have a positive or negative
   direction that is consistent with the destination masked curve.
5. Require the destination slope to remain directionally stable over
   the configured stability window.
6. Reject candidate handoffs that produce:
   - overshoot;
   - undershoot;
   - artificial local extrema;
   - oscillation;
   - slope reversal;
   - non-monotonic transition;
   - discontinuous level.

The search must be deterministic and reproducible from the declared
configuration.

============================================================
5. SHAPE-PRESERVING BRIDGE
============================================================

For a valid H and E:

    f <= H:
        RobustTarget(f) = BaseTarget(f)

    H < f <= E:
        RobustTarget(f) = monotonic_bridge(BaseTarget, MaskedEarPrint)

    f > E:
        RobustTarget(f) = MaskedEarPrint(f)

The bridge must be shape-preserving and monotonic in log-frequency.

Its endpoint values must equal the corresponding target and masked
EarPrint values.

The bridge must not overshoot or undershoot either endpoint.

The bridge must not introduce an artificial local maximum or minimum.

The bridge must not reverse slope unless the endpoint geometry itself
requires that behavior.

============================================================
6. CONTINUITY
============================================================

The level must be continuous at both transition boundaries:

    RobustTarget(H-) = RobustTarget(H+)

    RobustTarget(E-) = RobustTarget(E+)

No level discontinuity is permitted.

The bridge should preserve a natural slope progression. The
implementation may constrain endpoint slopes when necessary to
guarantee monotonicity and prevent overshoot.

Therefore, exact C1 slope equality is desirable but is subordinate to
the locked requirement that the bridge remain shape-preserving,
monotonic, and free of artificial extrema.

============================================================
7. FAILURE CONDITION
============================================================

If no stable compatible handoff can be found inside the configured
personal domain:

- do not invent a handoff;
- do not distort the BaseTarget;
- do not distort the MaskedEarPrint;
- report NO_STABLE_HANDOFF;
- preserve the mathematically defined curves rather than introducing
  an undocumented correction.

============================================================
8. CONFIGURATION
============================================================

The adaptive handoff is controlled by:

    adaptive_handoff.enabled

    adaptive_handoff.nominal_anchor_hz

    adaptive_handoff.min_transition_octaves

    adaptive_handoff.max_transition_octaves

    adaptive_handoff.stability_window_octaves

    adaptive_handoff.method

Current locked repository configuration:

    nominal_anchor_hz = 1000 Hz
    min_transition_octaves = 0.125
    max_transition_octaves = 0.8
    stability_window_octaves = 0.20

Method:

    earliest stable compatible handoff +
    monotonic cubic Hermite bridge

============================================================
9. SCOPE
============================================================

This addendum changes only the boundary handoff behavior.

It does NOT change:

- one-IEM-one-vote weighting;
- the three alignment bands;
- per-IEM median alignment;
- per-IEM alignment uncertainty;
- CrossIEM_MAD;
- TotalUncertainty;
- Retention;
- RawMask;
- Gaussian smoothing definition;
- high-frequency display-only extension;
- target discovery;
- IEM discovery.

The adaptive handoff is applied after the target-specific mask has been
calculated and after the masked target has been formed.

============================================================
10. VALIDATION REQUIREMENTS
============================================================

Every generated target must expose the adaptive handoff result in the
build report.

At minimum report:

- status;
- nominal anchor;
- selected handoff H;
- endpoint E;
- transition width in octaves;
- continuity result;
- monotonicity result;
- overshoot result;
- undershoot result;
- extremum/slope-reversal result.

The validation must be deterministic.

No visual judgement alone is sufficient to declare the boundary valid.
